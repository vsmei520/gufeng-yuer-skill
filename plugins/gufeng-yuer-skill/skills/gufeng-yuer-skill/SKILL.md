# 曾美团队·抖音 AI 短剧生产

这是远程授权入口，不包含核心 Skill 规则、业务提示词或服务器执行代码。

首次使用时发送：

```text
使用抖音 AI 短剧生产工作流。

选题：[你的选题]

初步构思：[你的构思]
```

必须只使用 `gufeng-yuer-skill` MCP 服务中的 `get_douyin_ai_drama_workflow` 工具。若该工具没有暴露、授权失败或远程服务不可用，必须停止并提示用户重新授权、重载插件或新建对话；严禁改用 `juqing-skill`、剧情带货、视频反推、Seedance 带货容器或任何其他插件/Skill 代替执行。

本项目不是剧情带货流程，不输出“产品分支”“带货/不带货”判定，除非用户明确要求商业带货改造。

首次连接会请求 OAuth 授权。若 Codex 主机支持安装时认证，会自动打开授权页；若没有打开，请访问 https://guoxue.073955.com/activate 完成授权码激活，再返回 Codex 重新连接插件，让客户端重新发起 OAuth。授权码、一机一码绑定、会话和核心工作流均由远程服务处理。

远程服务不可用或授权失败时停止，不使用未经授权的本地回退规则。换设备请联系管理员解绑。

未明确指定画幅时，所有资产提示词和 Seedance 提示词必须使用 `16:9` 横屏；不得因为抖音、短视频或源模板把 `9:16` 排在前面就自动选择竖屏。服务端会拒绝与本次画幅意图冲突的发布包。

完成场景图、人物多视图、站位图和所选 Seedance 提示词后，必须继续调用同一个工具的 `action=publish` 提交最终发布包。发布包至少包含封面提示词、3 个标题、5 个话题、发布简介、事实核验说明、资产提示词和 Seedance 提示词；如服务先返回字段契约，按契约补齐后再次提交。只有收到 `stage=published` 和结构化发布包后，才能向用户报告发布包已登记。服务未返回真实媒体文件或 URL 时，不得声称图片或视频已经生成。

## 阶段交付协议

启动后如果服务返回 `requires_submission=true`，必须根据用户输入和当前阶段规则生成完整业务成果。不能把 `core_setting_proposal`、`six_transformations`、`anti_template_selection`、`requires_submission`、`requires_confirmation` 等内部字段当成回复，也不能只说“工作流已启动”或只显示确认按钮。先生成完整正文，调用同一工具的 `action=submit_stage` 登记与将要展示的完全相同的正文，再把该正文直接展示给用户，并在正文末尾询问确认。
第一阶段必须严格按照新版剧本指令输出 `核心设定提案`，包含构思解剖、核心设定、设计理由和采用/调整/推翻选项；不得输出旧版《钩子节奏分析报告》，不得提前写完整剧本。用户确认后依次输出 `6 次转化`、`三大反模板全景选择`，每步都先登记再展示再等待确认。`6 次转化` 必须先给出 `已确认核心设定锁定`，逐项复述主角、核心困境、对照者、故事场景、关键象征物和结尾方向；`三大反模板全景选择` 必须先写 `承接已确认的 6 次转化`；`完整四列脚本初稿` 必须先写 `本稿锁定依据`。
用户回复“确认”后才调用 `action=confirm`。如果返回的下一阶段仍为 `requires_submission=true`，必须立即生成下一阶段的完整正文，登记后直接展示正文，再等待用户确认。后续阶段必须按服务器返回的契约逐步输出：完整四列脚本初稿、V4 精修计划与自动分段、V4 单段精修、V4 全篇整合、引擎选择、场景/人物多视图/站位资产、Seedance 第零阶段画面合理性诊断与评分、Seedance 单段提示词、Seedance 最终校验、最终发布包。只有阶段正文已经展示并登记后才能询问确认或下一步选择。
提交 `v4_plan` 或 `seedance_zero_diagnosis` 时，必须把分段总数作为 `total_segments` 一并提交。提交 `v4_segment` 或 `seedance_segment` 时，按服务器契约中的 `current_segment` 只输出当前段，并可携带 `segment_index`。用户说“确认”或“继续”后才进入下一段；不得把多段结果合并成一次无确认交付，也不得跳过 V4 全篇整合、Seedance 第零阶段诊断评分或最终校验。Seedance 阶段的正确顺序是：资产提示词确认后，只输出 `第零阶段：画面合理性诊断与评分`；用户确认后，才输出 `Seedance 2.5 提示词·第1段` 或 `Seedance 2.0 提示词·第1段`。
工具调用结果只用于内部推进和读取契约；对用户的回复只保留当前阶段的业务成果和必要的确认问题。不要向用户展示原始 JSON、阶段英文名、工具加载记录、对标 Skill 名称或“已进入下一阶段”的空消息。
用户可见正文中禁止出现 `<thinking>`、`</thinking>`、`思考过程`、`非常抱歉`、`发生了严重的内容错位`、`错误地套用了`、`修正版：`、`运行了命令`、`已读取文件运行了命令`、`List MCP resources` 等内部或纠错痕迹；若草稿出现这些内容，必须在提交前静默重写，不得展示给用户。Seedance 单段阶段禁止使用“Seedance 成片提示词与校验”或“分段 Seedance 提示词”总标题来一次性输出多个段落；标题必须类似 `Seedance 2.5 提示词·第1段`，并且本轮只给当前段。

最终发布包交付协议：当 `action=publish` 返回 `published=true` 时，必须把返回的
`publish_package` 完整展示给用户，不能只说“发布包已登记成功”。依次输出完整的
封面提示词、全部标题、全部话题、发布简介、事实核验说明、场景/人物多视图/站位
资产提示词、全部 Seedance 分段提示词、画幅和可选 AI 说明。只有展示完整正文后，
才可以补充“已登记”；没有真实媒体文件或 URL 时，不得声称图片或视频已经生成。
